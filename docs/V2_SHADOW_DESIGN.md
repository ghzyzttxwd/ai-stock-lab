# V2 影子系统设计（不接正式账本）

## 目标

V2 不是给 V1 多加几个指标，而是把决策过程拆成职业交易系统常见的层级：

1. 市场状态（regime）
2. 主线/行业强弱（leadership）
3. 个股资格与地位（selection）
4. 风险预算与仓位（sizing）
5. 失效条件与退出（exit thesis）
6. 成交仿真（execution）
7. 复盘与版本比较（evaluation）

V2 在验证完成前不得修改 `state/A.json`、`state/B.json`、`state/C.json`、`state/D.json`、`state/D_MAIN.json`、`state/L.json`，也不得改变 production workflow 的正式交易逻辑。

## 两种验证模式

### A. 前向影子盘（最终裁判）

从启用日起，每个交易日收盘后用当时可获得的数据生成 V2 目标，次一交易日开盘按与 V1 相同的成交假设执行，独立保存 V2 影子账本。

这是决定是否升级正式策略的主要证据，因为它天然避免“知道未来成份股/未来财报”的问题。

### B. 历史研发回测（只用于筛选）

历史回测只有在数据满足 point-in-time 条件时才可用于正式结论：

- 股票当日是否上市、退市、ST、停牌必须按当时状态判断；
- 财务指标只能在公告日之后使用；
- 行业/概念归属要注明是否为历史快照还是当前映射；
- 不允许使用今天仍存续股票构造过去的股票池后宣称“完整历史表现”；
- 不允许用当日收盘后才知道的数据成交在当日开盘；
- 所有目标仍执行“收盘决策 -> 下一交易日开盘”的 no-lookahead 规则。

若某项历史数据做不到 point-in-time，报告必须标记为 `research_only`，不得作为替换正式策略的唯一依据。

## V2 公共输入层

### 1. 市场状态 Market Regime

目标输出：`risk_on / neutral / risk_off / panic_rebound`，并给 0-100 置信分。

计划输入：

- 沪深300、中证500、中证1000趋势（20/60日、均线位置）
- 全市场上涨家数比例
- 20/60日创新高与创新低占比
- 涨停/跌停家数
- 炸板率、连板高度
- 全市场短期波动/回撤
- 行业扩散度：强势是否集中在少数行业

重要原则：市场状态必须基于全市场/指数，不再用“已经筛出来的候选股”反推大盘强弱。

### 2. 行业与主线 Leadership

目标输出：每只股票的 `industry_score`、`theme_score`、`leader_score`。

计划输入：

- 行业/概念近 5/10/20 日相对强弱
- 板块资金流排名（只作辅助，不把单日主力净流入当真理）
- 板块涨停数量与持续天数
- 个股在板块内涨幅/成交额/涨停地位
- 龙头持续性：不是只看“最高板”，还看带动性与板块共振

### 3. 个股技术与交易质量

在现有 `r20/r60/vol20/amount20` 基础上增加：

- 5日/10日/20日/60日收益
- 20/60日最高价距离
- 突破后回撤幅度
- ATR/真实波幅或等价波动指标
- 成交额趋势与异常放量
- 跳空幅度
- 近期涨停/炸板/连板信息（C 为主）
- 极端单日涨幅后的拥挤惩罚

### 4. 财务质量（A/L/D 使用）

只在公告后可用：

- ROE / ROA
- 毛利率、净利率及稳定性
- 营收同比、归母净利同比
- 经营现金流及现金流/净利润关系
- 资产负债率
- 估值 PE/PB（优先行业内相对估值，而非全市场统一阈值）

V2 禁止继续使用所有股票固定 `quality=70` 的占位做正式判断。

## 五只基金 V2 边界

### A — 保守稳健

赚钱逻辑：质量 + 低波动 + 防守型趋势。

- 先过滤财务质量差、现金流差、杠杆异常标的；
- 组合按风险贡献而非简单等权；
- 市场 `risk_off` 时显著降仓；
- 高波动纯题材股即使趋势强也降低资格；
- 目标换手低于 B/C/D。

### B — 趋势追强

赚钱逻辑：强行业中的健康趋势，而不是全市场直接按20日涨幅排序。

- 先选强行业，再选行业内个股；
- 看 20/60 日趋势、突破质量、回撤、成交额持续性；
- 急跌后的剧烈反弹阶段识别为 `panic_rebound`，降低机械追涨；
- 趋势失效是主要卖出理由。

### C — 短线快攻

赚钱逻辑：主线 + 情绪 + 龙头地位的收盘后版本。

- 重点使用涨停池、连板高度、炸板率、板块涨停扩散、行业资金活跃；
- 有清晰主线和核心才参与；
- 退潮期允许 0 仓位；
- 不模拟盘中排板/打板，继续坚持“收盘判断、次日开盘执行”；
- 目标持有期短，失去主线/龙头地位即退出。

### D — 综合判断

赚钱逻辑：由 Sol 在结构化信息上做组合级判断，但代码掌握硬风控。

Sol V2 输入应包含：

- market regime 及原因；
- 行业/主线排名；
- 每只候选技术、质量、估值、风险、行业地位；
- 当前持仓盈亏、持有天数、目标与实际仓位；
- 基金自身最大回撤/近期回撤；
- 行业集中度；
- 最近若干次决策和结果摘要。

硬规则仍由 deterministic code 执行：候选资格、单股上限、新仓上限、总仓位、100股整数、T+1、涨跌停、手续费、滑点、无行情/停牌拒绝成交。

### L — 长线价值

赚钱逻辑：盈利质量 + 合理估值 + 中期趋势确认。

- 财务质量是真实输入，不再固定占位；
- 估值优先行业相对 PE/PB；
- 高 ROE 但现金流长期差的公司降权；
- 财务恶化是主要退出理由之一；
- 价格趋势用于避免明显下跌趋势中机械抄底；
- 明显设置换仓门槛，降低手续费和噪声换手。

## 组合层（所有基金共用）

V2 必须新增：

- 风险预算 sizing：波动越大，目标仓位越小；
- 行业集中度上限；
- 高相关股票簇限制；
- 基金自身回撤刹车；
- 最低换仓优势阈值：新标的仅略优于旧持仓时不换；
- 每笔目标记录 `thesis`（为什么买）和 `invalidation`（什么条件说明买错）。

## 影子账本

建议独立目录：`shadow_state/v2/`。

每只基金独立保存：

- cash / positions / fills / equity_curve
- decision_date / execution_date
- strategy_version
- market_regime
- thesis / invalidation
- data_quality flags

影子账本不得被 production workflow 读取。

## 评估标准

至少同时比较：

- 累计收益
- 沪深300超额
- 最大回撤
- 年化/日化波动
- Calmar 或等价“收益/回撤”指标
- 换手率与手续费占比
- 空仓比例
- 行业集中度
- 单笔/单日尾部亏损
- 不同市场状态下的分项表现

### 升级门槛

V2 不因短期总收益更高就替换 V1。

优先满足：

1. 收益没有靠显著更高回撤换来；
2. 结果不是少数一两笔极端交易贡献；
3. 手续费/换手可接受；
4. 至少在多个市场状态下不出现明显结构性崩溃；
5. 前向影子样本达到约 20 个交易日后开始初评，60 个交易日后再做较严肃判断。

## 当前已确认可研究的数据接口

AKShare 官方文档当前列有：

- 涨停池/情绪类股票数据；
- `stock_sector_fund_flow_rank`、行业/概念资金流历史；
- `stock_financial_analysis_indicator`、同花顺/东方财富财务报表及主要指标；
- 创新高/创新低、市场拥挤度等相关接口。

这些接口仍需在 V2 分支上逐个做字段、稳定性、历史可得性和 point-in-time 验证后才能进入正式 shadow pipeline。

参考：AKShare 官方文档 https://akshare.akfamily.xyz/data/stock/stock.html 与 https://akshare.akfamily.xyz/data/index.html

## 开发顺序

1. `v2-shadow` 分支完成独立特征与策略框架；
2. 为 market regime / sizing / thesis / no-lookahead 写单元测试；
3. 做小样本历史研发回测，明确 bias 标记；
4. 建立不接 Sol 的 A/B/C/L 前向影子盘；
5. D 先用 deterministic fallback 跑影子，确认数据稳定后再接 Sol V2；
6. 达到验证门槛后再讨论是否合并到正式生产。
