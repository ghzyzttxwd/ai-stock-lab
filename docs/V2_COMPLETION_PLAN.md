# V2 影子盘完善计划

## 最高目标

在 `v2-shadow` 分支建立一套可长期前向验证的 V2 系统。它必须和 `main`、V1 正式账本完全隔离，不调用 Sol，以 100 万元虚拟本金独立运行 A/B/C/D/L 五只基金，并留下足以复算每次决策、成交和净值的审计证据。

## 不可突破的边界

- 不合并、不修改 `main`。
- 不读取或写入 `state/*.json`，不改变 V1 正式交易与网页发布。
- 不读取 `AI_API_KEY`，不调用 Sol 或其他付费 AI。
- V2 只能写入 `shadow_state/v2/` 和专属诊断产物。
- 决策使用当日收盘后可得数据，只能在下一交易日开盘模拟成交。
- 成交参数与 V1 保持一致：100 股整数、万三佣金且最低 5 元、卖出万五印花税、5 bps 滑点、T+1、涨停不可买、跌停不可卖。
- 数据不完整时保留旧账并明确失败，不用残缺行情推测成交。

## 阶段与验收

### P0 — 基线与隔离（已完成）

- `v2-shadow` 从 `main` 单向分出且不落后于分叉点。
- 最新标准化快照 smoke 成功。
- V2 数据、特征和目标生成均声明 `calls_sol=false`。

### P1 — 独立影子账本

- 新建 A/B/C/D/L 五份账本，每份初始现金 1,000,000 元。
- 首日只记录目标；下一有效交易日才按开盘成交。
- 挂单仅允许来自紧邻的上一交易日，过期目标不得补成交。
- 同一交易日重复运行必须幂等，不能重复成交、重复记净值或重复生成事件。
- D 使用确定性 fallback，不接 Sol。

验收：单元测试覆盖初始化、买卖、费用、滑点、100 股、现金约束、T+1、涨跌停、过期目标和重复运行。

### P2 — 不可回写审计

- 每日生成一个内容寻址的审计事件，记录数据版本与 SHA-256、目标版本、策略版本、市场状态、成交、未成交原因、费用、持仓、现金和收盘净值。
- 已存在的日期事件若内容不同则拒绝覆盖；相同内容视为安全重跑。
- 每笔目标保留 `thesis` 与 `invalidation`。
- 账本保存格式版本、执行规则版本和来源质量标记。

验收：测试证明历史事件不可改写，事件哈希可复算，账本汇总可由事件链核对。

### P3 — 数据与行业质量

- 决策快照与策略计算只抓一次并复用，不重复请求情绪接口。
- 申万行业映射记录唯一股票数、跨行业重复、缺失率和失败行业。
- 同花顺行业流只作独立交叉验证/备用信号，不冒充申万成分映射。
- 任何降级数据均显式进入 `data_quality`，未达到门槛时阻断新决策。
- 腾讯历史抓取增加持久缓存设计，优先增量补齐；并发保持小规模、带退避和耗时预算。

验收：覆盖率门槛、重复代码、空行业、陈旧数据、降级来源和缓存命中均有测试或 CI 诊断。

### P4 — B/C 集中与组合可解释性

- 硬执行现有单股和行业上限。
- 每日记录行业权重、最大行业权重、有效行业数、HHI、前两大行业占比。
- B/C 行业集中先作为前向诊断，不为追求表面分散而强行调参。
- 记录五策略两两持仓 Jaccard 重合度，并对持续高重合发出提示。

验收：组合统计可复算，B/C 触碰上限或集中度过高时有明确诊断。

### P5 — 独立运行与 CI

- 新增只针对 `v2-shadow` 的影子运行工作流；不得被 production workflow 读取。
- 工作流先测试，再生成当日快照/目标，再处理上一交易日目标，最后提交 `shadow_state/v2/`。
- 推送账本提交不能递归触发同一工作流。
- 输出阶段耗时、总耗时、缓存命中和数据源状态。
- 所有 V2 工作流共享外部行情锁，避免并发互相打垮公共接口。

验收：V2 单元测试、目标诊断、快照 smoke 和影子账本 smoke 全绿；日志证明未调用 Sol，且没有 V1 文件变化。

> GitHub 的 `schedule` 和 `workflow_dispatch` 都要求工作流存在于默认分支。在“绝不修改 main”的边界下，本阶段提供 `v2-shadow` 的受控 push 验证入口：更新 `shadow_state/v2/.run-trigger` 即可运行；完全自动的每日唤醒器必须等用户以后明确允许在默认分支增加一个只调度 V2 的极小工作流。

### P6 — 前向评估

- 20 个交易日开始初评，60 个交易日再做升级判断。
- 同时评估累计收益、沪深300超额、最大回撤、波动、收益/回撤、换手、费用占比、空仓比例、行业集中度和尾部单日亏损。
- 按 `risk_on / neutral / risk_off / panic_rebound` 分组评估。
- V2 在达到门槛前不替换 V1。

## 完成定义

本轮开发完成必须同时满足：

1. 五份 V2 账本能够独立初始化并安全推进交易日；
2. 关键成交规则与 V1 参数一致且有自动测试；
3. 历史审计事件不可被静默改写；
4. 数据、行业、集中度和耗时诊断能在 CI 中看到；
5. `main` 与 V1 正式账本无任何改动；
6. 相关 GitHub Actions 最终全部成功。

## 首轮前向基线（2026-08-14）

- 影子账本工作流通过；快照 244 秒、历史补全 191 秒、记账小于 1 秒，核心数据阶段合计 435 秒。
- A/B/C/D/L 均以 1,000,000 元现金建账并生成下一交易日开盘待执行目标；首日没有成交是预期行为，不允许用当日收盘信号回填成交。
- 审计链首事件通过内容哈希、父哈希和五本账本头指针校验；运行声明 `calls_sol=false`、`reads_v1_ledger=false`、`writes_v1_ledger=false`。
- B、C 首日均触发“有效行业数低于 2、单一行业占已投资仓位至少 60%、前两行业至少 85%”诊断。它们的绝对行业仓位仍受 38%/45% 硬上限约束，因此先保留为真实前向观察，不用单日样本调参。连续累计 20 个可成交会话后再判断：若过半会话仍触发，则优先加入第二行业候选配额或下调行业上限；不通过事后挑参数美化首日结果。
